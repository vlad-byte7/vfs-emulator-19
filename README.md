# VFS — эмулятор командной строки

Учебный проект по дисциплине «Конфигурационное управление».

**Вариант №19**

Программа имитирует работу командной строки UNIX-подобной
операционной системы.

Эмулятор реализован на Python с использованием графического
интерфейса Tkinter.

## Реализованные этапы

### Этап 1. REPL

Реализован графический интерфейс командной строки.

Функциональность:

- Создание графического терминала на Tkinter.
- Обработка команд, введённых пользователем.
- Разбор команд с использованием модуля shlex.
- Поддержка аргументов в одинарных и двойных кавычках.
- Реализация команд-заглушек ls и cd.
- Реализация команды exit.
- Обработка неизвестных команд.
- Обработка ошибок синтаксиса командной строки.

### Этап 2. Конфигурация

Добавлена возможность настройки эмулятора через параметры
командной строки.

Функциональность:

- Обработка параметров запуска с помощью argparse.
- Параметр --vfs для указания пути к виртуальной файловой системе.
- Параметр --script для указания стартового скрипта.
- Отображение параметров запуска в графическом интерфейсе.
- Чтение команд из текстового файла.
- Автоматическое выполнение команд стартового скрипта.
- Отображение ввода и результатов выполнения команд.
- Остановка стартового скрипта при первой ошибке.
- Обработка отсутствующих файлов скриптов.
- Проверка параметров запуска с помощью BAT-файлов.
- Автоматические тесты конфигурации и стартовых скриптов.

### Этап 3. Виртуальная файловая система (VFS)

Реализована загрузка виртуальной файловой системы
из ZIP-архива в оперативную память.

Функциональность:

- Загрузка ZIP-архива с использованием модуля zipfile.
- Работа с содержимым архива без распаковки на диск.
- Сохранение виртуальных каталогов в множестве set.
- Сохранение файлов в словаре dict.
- Автоматическое определение родительских каталогов.
- Поддержка вложенной структуры папок и файлов.
- Кодирование содержимого файлов в Base64.
- Поддержка текстовых и двоичных файлов.
- Сохранение загруженной VFS в состоянии приложения.
- Отображение количества загруженных файлов и каталогов.
- Обработка ошибок отсутствующих и повреждённых архивов.
- Проверка корректности путей внутри ZIP-архива.
- Автоматическое тестирование разных структур VFS.

Все операции загрузки выполняются в оперативной памяти.
Исходный ZIP-архив не распаковывается и не изменяется.

## Требования

Для запуска необходимы:

- Python 3.10 или новее.
- Tkinter с поддержкой графического интерфейса.
- Операционная система Windows для запуска BAT-файлов.

Все используемые модули входят в стандартную библиотеку Python.

Установка дополнительных зависимостей не требуется.

## Запуск программы

Откройте проект в VS Code.

Откройте терминал из корневой папки проекта.

### Обычный запуск

```powershell
py -m src.main
```

Откроется графический терминал эмулятора.

Также на Windows можно использовать файл:

```text
run.bat
```

### Запуск с виртуальной файловой системой

```powershell
py -m src.main --vfs filesystem.zip
```

Параметр --vfs определяет путь к ZIP-архиву,
содержащему виртуальную файловую систему.

Программа считывает содержимое архива в память
и отображает количество файлов и каталогов.

### Запуск со стартовым скриптом

```powershell
py -m src.main --script startup.txt
```

Параметр --script указывает путь к текстовому файлу
с командами, которые выполняются автоматически.

### Запуск с двумя параметрами

```powershell
py -m src.main --vfs filesystem.zip --script startup.txt
```

При таком запуске программа загружает виртуальную
файловую систему и выполняет стартовый скрипт.

### Просмотр параметров запуска

```powershell
py -m src.main --help
```

Команда отображает справку по доступным параметрам.

## Поддерживаемые команды

| Команда | Описание |
| --- | --- |
| ls | Выводит имя команды и переданные аргументы |
| cd | Выводит имя команды и переданные аргументы |
| exit | Завершает работу эмулятора |

На текущем этапе ls и cd являются заглушками.

Полноценная работа этих команд с виртуальной
файловой системой будет реализована на четвёртом этапе.

## Стартовые скрипты

Стартовый скрипт представляет собой текстовый файл,
содержащий команды эмулятора.

Каждая непустая строка рассматривается как отдельная команда.

### startup.txt

Пример успешного выполнения команд:

```text
ls
cd "Мои документы"
ls -l
```

Команды выполняются последовательно.

В графическом терминале отображается каждая команда
и результат её выполнения.

### startup_error.txt

Пример обработки ошибки:

```text
ls
unknown
cd documents
```

После выполнения неизвестной команды unknown
программа выводит сообщение об ошибке.

Следующая команда не выполняется.

При этом окно эмулятора остаётся открытым.

### startup_exit.txt

Пример завершения программы:

```text
ls
cd "Мои документы"
exit
```

После выполнения команды exit графическое окно закрывается.

## Виртуальная файловая система

Источником данных VFS является ZIP-архив.

Пример структуры:

```text
filesystem.zip
├── home/
│   └── user/
│       ├── notes.txt
│       └── program.py
└── images/
    └── photo.png
```

После загрузки структура каталогов представляется
в оперативной памяти множеством путей.

Пример:

```python
directories = {
    "/",
    "/home",
    "/home/user",
    "/images"
}
```

Файлы сохраняются в словаре.

Ключом является полный виртуальный путь к файлу,
а значением — его содержимое в кодировке Base64.

Пример:

```python
files = {
    "/home/user/notes.txt": "SGVsbG8="
}
```

Вложенные каталоги определяются автоматически,
даже если они не представлены отдельными записями
в ZIP-архиве.

Загрузка не создаёт настоящие папки и файлы на диске.

Данные виртуальной файловой системы сохраняются
в оперативной памяти до завершения приложения.

## Обработка ошибок

Эмулятор предусматривает обработку следующих ситуаций:

- Ввод неизвестной команды.
- Некорректное использование кавычек.
- Лишние аргументы команды exit.
- Отсутствие стартового скрипта.
- Ошибки чтения стартового скрипта.
- Отсутствие ZIP-архива.
- Повреждённый или некорректный ZIP-архив.
- Некорректные пути внутри виртуальной файловой системы.
- Неизвестные параметры командной строки.

Сообщения об ошибках выполнения команд
отображаются в графическом терминале.

При первой ошибке выполнение стартового скрипта
прекращается.

## Основные модули

### main.py

Точка входа в программу.

Получает конфигурацию и запускает графический интерфейс.

### gui.py

Реализует графический терминал на Tkinter.

Отвечает за:

- Создание окна приложения.
- Отображение команд и результатов.
- Обработку пользовательского ввода.
- Выполнение стартового скрипта.
- Загрузку виртуальной файловой системы.
- Обработку ошибок.
- Завершение работы приложения.

### parser.py

Содержит функцию parse_command().

Разбирает введённую строку на команду и аргументы
с учётом кавычек.

### commands.py

Содержит функцию execute_command().

Обрабатывает поддерживаемые команды эмулятора.

### config.py

Содержит функцию parse_config().

Использует argparse для обработки параметров запуска.

### script_runner.py

Содержит функцию read_script().

Читает команды из текстового файла,
пропуская пустые строки.

### vfs.py

Содержит функцию load_vfs().

Загружает ZIP-архив в оперативную память,
формирует структуры виртуальных файлов и каталогов.

## Автоматическое тестирование

Для тестирования используется стандартный модуль unittest.

Запуск всех тестов:

```powershell
py -m unittest discover -s tests -v
```

В проекте предусмотрено 24 автоматических теста.

Проверяется:

- Обработка команд ls, cd и exit.
- Обработка неизвестных команд.
- Пустой пользовательский ввод.
- Разбор аргументов в кавычках.
- Обработка незакрытых кавычек.
- Передача параметров запуска.
- Чтение стартовых скриптов.
- Обработка отсутствующего скрипта.
- Остановка выполнения скрипта при ошибке.
- Загрузка минимальной виртуальной файловой системы.
- Загрузка нескольких файлов.
- Загрузка вложенных каталогов.
- Кодирование двоичных данных.
- Отсутствие распаковки файлов на диск.
- Обработка отсутствующего ZIP-архива.
- Обработка некорректного ZIP-архива.
- Отклонение недопустимых виртуальных путей.

Для тестов VFS используются временные ZIP-архивы,
создаваемые с помощью tempfile и zipfile.

После завершения тестов временные архивы удаляются.

## Ручное тестирование

Для Windows подготовлены BAT-файлы.

### test_launch.bat

Проверяет запуск программы:

- Без параметров.
- Только с параметром --vfs.
- Только с параметром --script.
- С двумя параметрами одновременно.

### test_errors.bat

Проверяет обработку ошибок:

- Ошибочная команда в стартовом скрипте.
- Отсутствующий файл стартового скрипта.
- Неизвестный параметр командной строки.

### test_vfs_basic.bat

Создаёт тестовые ZIP-архивы и проверяет:

- Минимальную VFS с одним файлом.
- VFS с несколькими файлами.

### test_vfs_nested.bat

Создаёт тестовый ZIP с вложенными каталогами
и проверяет его загрузку.

Дополнительно проверяет выполнение стартового
скрипта с ошибкой.

Каждый BAT-файл запускается из корня проекта.

Для перехода к следующему графическому запуску
необходимо завершить предыдущий.
